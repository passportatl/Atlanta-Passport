Implement Sprint 1 of Passport ATL’s automatic event ingestion system, including both iCal sources and Ticketmaster.

Primary objective:

Build and verify a reliable automatic event ingestion pipeline that imports Atlanta-area events from:

1. Ticketmaster
2. Twenty to thirty legitimate Atlanta-area iCal or ICS feeds

All newly imported events must enter the Passport ATL CMS as Pending Review and must not be automatically published.

Before making changes:

* Review the existing event ingestion architecture.
* Reuse the current event schema, source manager, import logging, deduplication, and Pending Review workflow wherever possible.
* Preserve all existing manual events and Google Sheets imports.
* Do not remove or disable any functioning source integrations.

## Deduplication

Use the existing deduplication system and strengthen it where necessary.

Check the following signals:

* source event ID
* normalized title
* start date and time
* end date and time
* venue name
* address
* latitude and longitude
* event URL
* ticket URL

Prevent duplicate records when:

* the same event appears in Ticketmaster and an iCal feed
* the same event appears in multiple iCal feeds
* a source republishes or modifies an existing event
* recurring events contain repeated instances
* an event title varies slightly between sources

Use exact external IDs as the strongest match.

For cross-source matching, use a weighted comparison based on normalized title, date and time, venue, address, and URL.

When a probable duplicate exists:

* update the existing record only when the source data is more complete or newer
* preserve source references when possible
* otherwise skip the duplicate and log the reason

Do not silently overwrite manually edited CMS fields.

## Recurring events

Handle recurring iCal events safely.

Support:

* recurrence rules
* recurrence exceptions
* modified instances
* cancelled instances
* event series identifiers

Do not generate unlimited future occurrences.

Use a reasonable import horizon, such as the next twelve months, unless the existing system already defines a different horizon.

Each occurrence should remain traceable to its source event and recurrence identifier.

## Pending Review workflow

All newly imported Ticketmaster and iCal events must:

* be assigned Pending Review status
* remain unpublished
* retain source attribution
* be reviewable in the CMS
* show whether they came from Ticketmaster or a specific iCal source

Do not alter the publication status of existing events.

Do not overwrite editorial changes made after an event has been reviewed unless the update is limited to protected source-controlled fields, such as cancellation status or source URL.

## Automatic synchronization

Configure reasonable recurring sync schedules.

Suggested defaults:

* Ticketmaster: every six hours
* active iCal feeds: every twelve hours
* recently failing sources: retry with controlled backoff
* disabled sources: do not sync automatically

Prevent overlapping sync jobs for the same source.

Log every sync attempt.

A failed source must not stop other sources from syncing.
